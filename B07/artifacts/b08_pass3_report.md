## 1. 第三遍要证明什么（文档 p.95 原文）

> 第三遍 | 做同题对照、失败验证和运行追踪：证明"为什么会变"
>
> 这一遍只做三种证明：
> - **证明一** | 改变一个主要条件，结果是否产生可解释变化。
> - **证明二** | 主动制造一次真实失败，系统是否能够可信降级。
> - **证明三** | 选择一个 run_id，最终判断是否能够反向追溯到输入、工具、证据和模型版本。
>
> 这一遍**不要再增加场景**。重点从"每个场景分别能不能跑"转向：
> **场景之间的变化，能不能被解释和追踪。**

本遍**没有新增场景**。所有对照都在第二遍已经固定的 S1~S5 之内。

### 本遍的 run 引用

第二遍的产物（`B07/b08.py`、`B07/artifacts/b08_validation_records.jsonl`）**都在**，
所以本遍**优先引用第二遍的正式 run_id**（`run_121`~`run_125`）；
文档点名的靶子（`run_012` / `run_015` / `run_023` / `run_057` / `run_084`）作为**交叉核对**
一并算了，**结论一致**。

**唯一新跑的一次**：`run_126` —— 证明二主动制造的失败（消耗 1 次 LLM 额度）。

## 2. 证明一摘要：四组对照 + 三条因果证明

机器判定**直接复用视图四的 C1~C5 与 R1~R6**，不另写一套口径。

### 四组对照（一句话结论）

| 组 | 对照 | 干净？ | 一句话结论 |
|---|---|---|---|
| **A** | S1 ↔ S2 | ✔ 干净（要证明的就是历史变了） | **历史过程不同**（首尾差 -1.1℃ vs +7.5℃、单调上升 False vs True、波动 1.3℃ vs 7.5℃）→ **趋势不同**（稳定 vs 持续上升）→ **当前状态理解随之变化**；C1~C5 **全 PASS**，归因 R2 |

| **C** | S1 ↔ S3 | ★ **干净（唯一变量）** | **唯一变量 = 是否接入外部天气**（history 0/6 点不同、window/current_state/model_output/analysis_time/问题指纹全同）→ 稳定判定与 B06 预测**都没变**，只有合成关注等级从 `internal_only` 变成 `watch_external` |
| **D** | S4 ↔ S5 | ✔ 干净（唯一变量） | **唯一变量 = B03 的 status**（ok/opposing → unavailable/undetermined）→ `has_conflict` True→False，CA `conflict_unresolved`→`watch_internal`；**S4 是"挂起"（相反列写得出反方），S5 是"退让"（相反列是空的，待定列写"这条没取到"）** |

### 三条因果证明（纯函数重算，零 LLM 消耗）

| 证明 | 改了哪个输入 | 重算了什么 | 输出怎么变 | 结论 |
|---|---|---|---|---|
| **CA-1** | `run_bundle.history`（S1 的 history 塞进 S2） | `build_judgement` | `stability_verdict`：不稳定 → **稳定** | **历史过程真正参与了当前状态理解** |
| **CA-2** | `external_conditions`（S3 的置 None） | `build_combined_attention` | `combined_attention.value`：watch_external → **internal_only** | **外部条件真正参与了未来判断，不是只显示在页面上** |
| **CA-3** | 台账里 **B03 那一条**（S4 的塞进 S5） | `build_evidence_divergence` + `build_combined_attention` | `has_conflict`：False → **True**；CA：watch_internal → **conflict_unresolved** | **「分歧」与「缺失」的差别就落在这一条证据上** |

★ 三条重算**只在内存里做**：不落盘、不产生 run、不进索引；
**沿用原存档的 `model_output`**（B06 预测不在重算范围内）。

## 4. 证明三摘要：12/12 环节 + 自检结论

❶ 问题 → ❷ 当前状态 → ❸ 历史窗口 → ❹ 工具调用 → ❺ 采用/未采用 → ❻ 天气

   把存档的 `history` 重新喂给 `judge_stability` 重跑，得到的还是「不稳定」。

## 6. 已知缺口（诚实写）

* **组 B 不干净** —— S2↔S3 同时变了 history 序列、history_window、稳定判定、
  current_state.lux 与 analysis_time，**不足以单独归因外部条件的作用**；
  外部条件的主证据是组 C（S1↔S3，唯一变量）。组 B 照文档做了，但没写成干净对照。
* **因果证明只覆盖"改一个输入"** —— CA-1/2/3 证明的是"在这一套判据下，
  改这个输入会让输出跟着变"，**不构成完备性证明**：
  没有枚举"还有没有别的输入能产生同样的效果"。
* **因果证明里 B06 预测未被改动** —— 重算沿用原存档的 `model_output`
  （B06 预测不在重算范围内），所以这些证明说明的是"判据层如何响应输入变化"，
  **不是**"模型层如何响应输入变化"。
* **证明二只制造了"天气不可用"这一种失败** —— 参数错误、超时、空结果、
  知识检索失败**尚未覆盖**；而且这次失败是**离线夹具 + 显式开关**，
  不是真实天气 API 故障，真实链路上的失败本轮**未覆盖**。
* **若第二遍尚未完成，本遍引用的 run 仍是 B07 开发期存档** —— 本遍第二遍**已完成**，
  所以正式对照优先引用 `run_121`~`run_125`；文档靶子那一对仍是 B07 开发期存档，
  已在证明一里逐组标注。
* **S4 / S5 的证据差异在现实链路上未经真实天气验证** —— 两者的 B03 都是
  `provider=Offline-Fixture` 的离线夹具，"方向相反"与"不可用"这两种形态固定下来了，
  但它们与真实天气 API 的对应关系本轮未验证。

## Limitations

* **L1** 组 B（S2↔S3）同时变了历史窗口与稳定判定，
  **不足以单独归因外部条件的作用**；干净对照是组 C（S1↔S3）。
* **L2** 因果证明（CA-1/2/3）证明的是"在这一套判据下，改这个输入会让输出跟着变"，
  **不等于**证明模型内部机制如此。
* **L3** 因果证明重算时**沿用原存档的 `model_output`**（B06 预测不在重算范围内）。
* **L4** 因果证明的重算**不落盘**，不产生 run，不进索引。
* **L5** 证明二只制造了"天气不可用"一种失败；参数错误、超时、空结果、
  知识检索失败**尚未覆盖**。
* **L6** S4 与 S5 的实质区别是**证据状态**，不是 scenario 字符串 ——
  仓库里 `scenario="S5"` 实际混着"分歧"与"缺失"两种状态
  （`run_082` 标着 S5，但 B03 是 ok、照样有分歧）。
* **L7** 本遍的对照与追踪是**离线复算 + 存档读取**，不重新消耗 LLM；
  只有证明二那次主动失败运行消耗 1 次额度。
* **L8** 若第二遍尚未完成，本遍引用的 run 均为 B07 开发期存档，
  不是 B08 正式验证记录。**本轮第二遍已完成**，正式对照已优先引用
  `run_121`~`run_125`；文档靶子那一对仍属 B07 开发期存档，已逐组标注。
