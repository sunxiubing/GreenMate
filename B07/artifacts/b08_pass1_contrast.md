机器判定：C1 ✅；C2~C5 ⚠️（序列相同，非漂移对）。归因命中 **R1**，归因层：

> · 同一份外部证据从「ok」变成「unavailable」
> · 分歧退化为缺失
> · 系统退让到只看内部证据（关注等级 conflict_unresolved → watch_internal）
> · ★ 关键：稳定性判定与 B06 预测（WATCH）**都没变**，变的是关注等级 —— 变化来自**证据层**

### ★ 两者表达不确定性的方式**不一样**

| | S4（证据都在，方向不一致） | S5（某一类证据根本不可用） |
|---|---|---|
| `resolution` | 「证据方向不一致，系统不强行合并，也不投票」 | 「证据方向一致」 |
| 三列 | 支持 3 / 相反 **1** / 待定 2 | 支持 3 / 相反 **0** / 待定 **3** |
| 相反列里写什么 | B03 的**具体方向与依据**："外部信号判定为 external_improving（相对差分）：降水概率 50.0% → 10.0%…" | **空** —— 没有相反方向 |
| 待定列里写什么 | B03 的**取数局限**（"取到的是基准日末点实测值…允许的日变化幅度"）+ B04 的证据强度 | B03 的**不可用状态与失败原文**（"外部天气证据当前不可用：status=unavailable…" + "weather provider unavailable (B07_WEATHER_UNAVAILABLE=1): …"）+ B04 的证据强度 |
| 关注等级 | `conflict_unresolved`（挂起，等人裁决） | `watch_internal`（退让到只看内部证据） |
| 限制条目 | `evidence_unavailable` **不出现**（没有不可用的证据） | `evidence_unavailable` **出现**，逐条列出不可用来源与 error 原文 |

> ★ **一句话**：S4 是"**证据都在但方向不一致**"→ 系统**挂起**（`conflict_unresolved`），
> 相反列里写得出反方是谁；S5 是"**一类证据根本不可用**"→ 系统**退让**
> （`watch_internal`），相反列是空的，待定列里写的是"这条没取到"。

### ★ 诚实指出：S4 与 S5 的实质区别是**证据状态**，不是 scenario 字符串

仓库里 `scenario="S5"` 这一组**实际混着两种状态**：

| run | scenario | B03 status | B03 direction | has_conflict | combined_attention |
|---|---|---|---|---|---|
| `run_082` | S5 | **ok** | opposing | True | conflict_unresolved |
| `run_084` | S5 | unavailable | undetermined | False | watch_internal |
| `run_125` | S5 | unavailable | undetermined | False | watch_internal |

也就是说，**`scenario` 标签并不等于"证据退化"** —— `run_082` 标着 S5，
但它的天气证据是好的、照样有分歧。**判别依据是台账里 B03 那条的 `status`**，
不是 scenario 字符串。

## 本材料的 Limitations

* **L1** 组 B（S2↔S3）同时变了历史窗口与稳定判定，
  **不足以单独归因外部条件的作用**；干净对照是组 C（S1↔S3）。
* **L2** 因果证明（CA-1/2/3）证明的是"在这一套判据下，改这个输入会让输出跟着变"，
  **不等于**证明模型内部机制如此。
* **L3** 因果证明重算时**沿用原存档的 `model_output`**（B06 预测不在重算范围内）。
* **L4** 因果证明的重算**不落盘**，不产生 run，不进索引。
* **L6** S4 与 S5 的实质区别是**证据状态**，不是 scenario 字符串 ——
  仓库里 `scenario="S5"` 实际混着"分歧"与"缺失"两种状态。
* **L7** 本遍的对照与追踪是**离线复算 + 存档读取**，不重新消耗 LLM。
* **L8** 本遍引用的 run 里有 B07 开发期存档（文档靶子那一对），
  也有第二遍的正式验证记录；两者结论一致。
