# B03 Weather Service 设计文档：接口异常与缓存策略

## HTTP 400 失败时不返回旧缓存的原因

当 Open-Meteo API 返回 HTTP 400（如纬度超出 -90~90°）时，B03 选择直接返回 None 而不是回退到上次缓存的成功数据。

### 核心原则：Fail Loudly（显式失败优于静默降级）

**静默返回旧数据的危害（phantom data）：**
- 下游系统不知道数据已过期，以为拿到的是最新有效数据
- 温室调控决策基于过时信息，可能导致作物受损
- 问题隐蔽，可能潜伏数天才被发现，排查困难
- 违反 API 隐含契约：成功响应代表数据完整

**显式返回 None 的好处：**
- 上游调用方立即感知数据不可用（if result is None）
- 监控系统能感知系统降级，触发告警
- 问题在 5 分钟内可被发现和修复
- 保持 API 信任契约：成功=数据有效，失败=数据无效

## 缓存策略取舍

B03 weather_service.py 的 fetch_current_weather() 函数：
- 成功时缓存结果到 self._cache（内存）
- HTTP 400 → **不缓存，直接返回 None**
- HTTP 429（限流）→ **不缓存，直接返回 None**
- timeout → **不缓存，直接返回 None**

**为什么不缓存失败？**
缓存失败结果会导致下次重试时直接返回上次的错误，阻止后续成功请求，形成"永久失败"状态。

**为什么不返回上次成功缓存作为降级？**
因为 HTTP 400 是请求参数错误（纬度格式错误），不是临时性故障。重新发请求（修正参数后）一定能成功，所以不需要降级到过期数据。

## 标准化错误响应模式

B03 推荐的错误响应结构：
```python
{
    "code": "WEATHER_API_ERROR",
    "message": "Open-Meteo API 返回 400：纬度超出范围",
    "retryable": False,      # 400 参数错误，不可重试
    "traceId": "xxx"         # 本次请求追踪 ID
}
```

关键区分：
- `None` vs 空列表 `[]`：`None` 表示数据获取失败，`[]` 表示数据为空（有效状态）
- `0` vs 不可用：温度 0°C 是有效值，`None` 表示不可用
